日期：2026-09-30

线上：http://39.106.101.94/eve/?view=qc
诊断阶段**未改动任何源文件**；老师选定方案 A2 后**已按 A2 实施并上线**（见 §7）。
全部结论来自把线上页面加载进无头浏览器后读取 ECharts 实例的真实坐标（`grid[i].coordinateSystem.getRect()`），不是目测。

---

## 1. 结论

留白大不是渲染 bug，是 `rQc()` 里**三块 grid 的 `top`/`height` 硬编码百分比与各自类目数不匹配**造成的：
第一块只画 2 根柱却分到 30% 高度（每根柱独占 102.8 px，柱本身只有 26 px），
块与块之间又留了 97.3 px / 54.8 px 的空档，**整张画布 34% 是纯空白**。

同一段代码里 `top` 还混用了像素（`26`）与百分比（`'48%'`），导致块间距随视口高度非线性变化。

---

## 2. 实测几何（viewport 1600×950，`#chart` 高 685 px）

声明值（源码第 821–825 行）：

```js
grid: [
  { left: 150, right: 90, top: 26,     height: '30%' },
  { left: 150, right: 90, top: '48%',  height: '18%' },
  { left: 150, right: 90, top: '74%',  height: '18%' }
]
```

实测值：

| grid | 声明 | 实际 y | 实际高 | 底边 | 类目数 | **band（每类目高度）** |
|---|---|---|---|---|---|---|
| 0（案例） | top 26 px, h 30% | 26.0 | 205.5 | 231.5 | 2 | **102.8 px** |
| 1（phiX174） | top 48%, h 18% | 328.8 | 123.3 | 452.1 | 8 | **15.4 px** |
| 2（类病毒） | top 74%, h 18% | 506.9 | 123.3 | 630.2 | 2 | **61.6 px** |

- 块间距：**97.3 px**（grid0→grid1）、**54.8 px**（grid1→grid2）
- 画布底部残余：54.8 px
- **空白合计 232.9 px = 画布 34.0%**

对比：同一页面 5 个单 grid 视图的空白占比只有 **5.5%–17.8%**（`virus` 5.8 / `host` 5.5 / `dnarna` 7.6 / `matrix` 17.8 / `past` 10.5）。
`amp` 视图（2 grid）同病且更重：缝 **130.4 px**、空白 **38.0%**。

**判据（可复现）**：band = `grid.height / 类目数`；健康的多面板布局 band 应大致同量级、块间距 ≤ 最矮面板的高度。
此处 band 跨 6.7 倍（15.4 → 102.8），且 97.3 px 的缝**几乎等于第二块面板的整块高度**（123.3 px）。

---

## 3. 根因（4 条，按贡献排序）

1. **`grid[0].height = '30%'` 只服务 2 个类目** → 2 × 102.8 px 的槽位里放 26 px 的柱子，每行白扔 77 px。这是最刺眼的一处。
2. **块间 `top` 差值按整张画布定**（26 → 48% → 74%），没考虑每块自己只有 18% 高 → 缝比面板还高。
3. **`top` 单位混用**：`26`（px）vs `'48%'`/`'74%'`（%）→ 视口变高时三个缝的变化率不一致，布局不稳定。
4. **`left: 150` 三块共用**：只有第二块的 y 轴标签（`Momordica_charantia_v1.0` 之类组装名）需要 150 px；第一、三块标签很短（`Datiscaceae (Datisca)`、`CEVd-like`），跟着一起右移，左侧多出一条空白带。

## 4. 顺带发现（不在「间隔」问题内，但同页）

- **第二块的排序键与绘图口径不一致**（`index.html:818` 与 `:847`）：数组按 `phi`（**绝对条数**）降序取前 8，画出来的却是 `pct`（**百分比**）。两者不一致的直接后果：`Leavenworthia_alabamica_v1.0`（1/1 = **100%**）和 `Iberis_amara_v1.0`（1/2 = 50%）被挤出前 8，而 `Pinus_taeda_v1.0`（1/4927 = **0.0%**）被画进来。反过来若改按 `pct` 排序，则会先把 `tot=1`、`tot=2` 的噪声基因组顶上来——**需要分母下限**。图例文字写的是 "share of viral_supported loci"（份额），与「按条数取 top」是两套口径。**属判定语义，未改，等老师定方向。**
- **图例色与实际柱色不一致**（`:860-862` vs `:847`）：图例给 phiX 的色块是 `#c0392b`（红），实际只有 `pct > 50` 的柱是红色，其余是 `#e67e22`（橙）；图例给类病毒的色块是 `#16a085`（绿），而 "other viroids" 那根柱是 `#bdc3c7`（灰）。
- **第一块的对数轴 10→100 与数据 19/23 不匹配**：两根柱只占到坐标区宽的 27.9% / 36.2%，右侧 64% 是空的。这是第二处横向留白来源。
- **第三块 "other viroids"（值 3，轴 0–1500）的柱高约 0.2%**，肉眼不可见，只有一个 "3" 的数字标签。

## 6. 复现方式

`docs/eve/work/probe_qc_layout.py`（本报告所用的探针，只读线上页面，不改仓库文件）：
加载 `?view=qc` → 读 `grid[i].coordinateSystem.getRect()` 与 `yAxis[i].data.length` → 打印 band / 间距 / 空白占比；
再用 `setOption({grid:[…]})` 注入候选布局截图。

**踩坑记录**：`setOption` 只标脏，实际渲染在下一帧。注入布局后立刻截图会截到**旧位图**（而几何读的是 model，已经是新值），
极易误判成「改了没生效」。注入后必须等一帧或调 `inst.getZr().refresh()` 再截图。
