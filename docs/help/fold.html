Batch Folding Queue (fold_web)

ColabFold console: collect → predict → ingest, for the UniProt Structure Atlas

What it is

An operations console (module 16.fold_web) that closes the structure-coverage gap of the UniProt Structure Atlas. It drives a single-worker job queue: collect (fetch FASTA from UniProt by accession) → predict (colabfold_batch subprocess) → ingest (best rank_001 model + mean pLDDT check) → index update (structures_index.tsv sources += SELF, model saved to structures_selffold/). Manual channels: upload FASTA, or upload a ColabFold results ZIP to ingest directly.

Where it runs (two deployments, 2026-10-07):   ① GPU server (full mode) — all four stages live; bind 127.0.0.1:8800, reach it via SSH forwarding ssh -L 8800:127.0.0.1:8800 <gpu-server>.   ② 39.106.101.94 (no-GPU mode, limited launch) — http://39.106.101.94/foldweb/ behind Basic Auth (credentials in the local password manager). The predict stage is disabled there (no GPU; jobs fail with a notice), while upload-results ZIP / Foldify export / coverage stats work. After ingesting there, rerun webapp/build_data.py on the server so the online Atlas pages pick up the new coverage.

Quick Start

  1. Coverage panel (top) refreshes live: own-structure %, BFVD homolog %, per-species completeness
  2. New job: paste UniProt accessions (comma/space/newline separated). The input box validates format and de-duplicates as you type. "填入全部待预测" loads the full pending list (3,698 proteins) after a confirmation
  3. Upload FASTA: bring-your-own sequences (title line must be the accession); drag-and-drop supported, upload progress shown
  4. Upload results ZIP: ran ColabFold elsewhere (or via Foldify)? Pack the output directory and ingest directly
  5. Job table: filter by status (running / done / failed), follow per-job logs (auto-scroll), retry failed jobs, delete finished ones

Foldify manual channel

For small top-ups without the GPU box: the export button packages pending ≤600 aa sequences into 100-per-file FASTA blocks with a manifest. Submit them manually at Foldify (free, no login, concurrency 5, no API), then upload the resulting ZIP back here. Do not automate bulk submissions against Foldify — fair-use limits; the bulk (3,394 proteins) belongs on local ColabFold.

Scope & limits

CaseGuidance
304 polyproteins >2,700 aaNot folded directly; split into domains first (list in colabfold_input/batch_polyprotein/). AF3 token budget can take the longest (3,471 aa) if you accept the cost — see the AlphaFast channel in the module README
~55 proteins <50 aaRunnable but of limited reference value
Job logs & workdirsKept under colabfold_input/jobs/; the queue database is colabfold_input/fold_jobs.db (SQLite). Delete jobs in the UI removes the record, not the files

Configuration (environment variables)

  • FOLDWEB_MODULE_DIR — data module root (default ../15.uniprot_plant_virus_structures)
  • FOLDWEB_PREDICT_CMD — predict command template with {input}/{output} placeholders (default uses colabfold_batch --msa-mode mmseqs2_uniref_env --num-models 3 --num-recycle 3 --model-type alphafold2_ptm --rank plddt)
  • FOLDWEB_HOST / FOLDWEB_PORT — bind address (default 127.0.0.1:8800)
